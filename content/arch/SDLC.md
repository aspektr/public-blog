Жизненный цикл разработки программного обеспечения (SDLC) — это структурированный процесс разработки качественного программного обеспечения. Он описывает шаги и лучшие практики, которым команды следуют от первоначального планирования до развертывания и поддержки.

✅ **Цель**: Доставка эффективного, надежного и масштабируемого ПО с минимальными рисками.  
✅ **Обеспечивает**: Ясное планирование, правильное тестирование и плавное развертывание.

### 1. Фазы SDLC

SDLC состоит из 6-7 основных фаз в зависимости от методологии (Waterfall, Agile и т. д.).

| Фаза                          | Описание                                                        | Ключевые результаты                                                                                    |
| ----------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **1. Планирование**           | Определение объема проекта, осуществимость, риски               | План проекта, отчет о целесообразности                                                                 |
| **2. Анализ требований**      | Сбор и анализ бизнес-требований                                 | [[BRD vs FSD\|BRD, FSD]], пользовательские истории, [[Матрица прослеживаемости требований - RTM\|RTM]] |
| **3. Проектирование системы** | Определение архитектуры, UI/UX, структуры базы данных           | Документ проектирования системы, Wireframes                                                            |
| **4. Разработка**             | Разработка приложения на основе проектных спецификаций          | Исходный код, API, модули                                                                              |
| **5. Тестирование**           | Проверка функциональности, безопасности и производительности ПО | Тестовые планы,test cases, отчеты о дефектах                                                           |
| **6. Развертывание**          | Выпуск ПО в продуктивную среду                                  | Развернутая система, Release Notes                                                                     |
| **7. Поддержка**              | Мониторинг, обновление и исправление проблем                    | Исправления ошибок, улучшения системы                                                                  |

### 2. Модели SDLC (Методологии)

Разные проекты используют различные модели SDLC в зависимости от требований и гибкости.

|Модель SDLC|Лучше всего для|Преимущества|Недостатки|
|---|---|---|---|
|**Waterfall**|Простые, последовательные проекты|Четкие этапы, структурированность|Жесткая структура, медленно адаптируется|
|**Agile**|Быстро меняющиеся, итеративные проекты|Гибкость, ориентированность на клиента|Требует сильной совместной работы|
|**Scrum**|Короткие итерации (спринты)|Быстрая доставка, адаптивность|Требует дисциплинированных команд|
|**DevOps**|Непрерывная интеграция и доставка|Автоматизация развертывания|Требует сильной автоматизации|
|**V-Model**|Высокий риск в отраслях (банковские, медицинские)|Строгое тестирование|Медленный процесс|
|**Spiral**|Крупные, сложные проекты|Управление рисками|Дорогая и трудоемкая|

### 3. Почему SDLC важен

✅ **Лучшее планирование** → Избегаются дорогостоящие ошибки.  
✅ **Обеспечение качества** → Ошибки обнаруживаются до развертывания.  
✅ **Эффективная разработка** → Снижает затраты времени и усилий.  
✅ **Снижение рисков** → Раннее выявление уязвимостей в безопасности.  
✅ **Плавное развертывание** → Обеспечивает минимальное время простоя.

### 4. Пример применения SDLC

📍 **Сценарий**: Создание веб-сайта электронной коммерции

| Фаза                  | Что происходит?                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------- |
| **Планирование**      | Определение целей проекта (например, "Пользователи должны иметь возможность покупать товары онлайн"). |
| **Анализ требований** | Идентификация бизнес-потребностей: вход пользователя, оформление заказа, интеграция платежей.         |
| **Проектирование**    | Создание макетов интерфейса, схемы базы данных и структуры API.                                       |
| **Разработка**        | Разработчики делают backend и frontend сайта.                                                         |
| **Тестирование**      | QA команда выполняет тесты для проверки безопасности, обработки платежей и интерфейса.                |
| **Развертывание**     | Сайт запускается в продуктивную среду после успешного тестирования.                                   |
| **Поддержка**         | Разработчики исправляют ошибки, оптимизируют производительность и выпускают обновления.               |

### 5. SDLC в Agile vs. Waterfall

📌 **Waterfall (Традиционный)** → Последовательные шаги, меньше гибкости.  
📌 **Agile (Современный)** → Итеративный, непрерывная обратная связь, частые релизы.

|Аспект|Waterfall|Agile (Scrum, DevOps)|
|---|---|---|
|**Планирование**|Полное планирование проекта в начале|Итеративное планирование|
|**Гибкость**|Низкая (изменения дорого обходятся)|Высокая (легко вносить изменения)|
|**Тестирование**|После завершения кодирования|Непрерывное тестирование|
|**Время доставки**|Долгое (6-12 месяцев)|Быстрое (2-4 недели на спринт)|
|**Управление рисками**|Высокий риск (поздняя обратная связь)|Низкий риск (ранняя обратная связь)|

### 6. Лучшие практики для SDLC

✅ Определите четкие требования до начала разработки.  
✅ Соблюдайте стандарты разработки и лучшие практики.  
✅ Используйте автоматическое тестирование для ускорения циклов QA.  
✅ Мониторьте производительность системы после развертывания.  
✅ Документируйте все (BRD, FSD, RTM, тестовые планы).
