**Двухфазный коммит (2PC — Two-Phase Commit)** — это алгоритм, который обеспечивает согласованное выполнение распределенных транзакций, когда транзакция затрагивает **несколько ресурсов или систем**, находящихся на разных узлах или серверах.

Данный механизм является стандартом в системах, требующих надежных транзакций на нескольких узлах (например, распределенные базы данных, микросервисы, транзакционные хранилища данных).

---

## 📌 **Зачем нужен двухфазный коммит?**

Когда транзакция затрагивает **несколько разных узлов или систем**, возникает проблема:

- Как убедиться, что либо все участники транзакции подтвердили выполнение операций (commit), либо все вместе отказались от них (rollback)?
- Нужно гарантировать, что не возникнет ситуации, когда одна часть транзакции применена, а другая — нет.

Именно для решения этой проблемы и применяется двухфазный коммит.

---

## 📍 **Как работает двухфазный коммит (2PC)?**

Алгоритм состоит из **двух последовательных фаз**:

### ✅ **Фаза 1: Подготовка (Prepare Phase)**

Координатор транзакции (**Transaction Coordinator**) отправляет всем участникам транзакции (**Transaction Participants**) запрос на подготовку к транзакции:

- Каждый участник проверяет, может ли он успешно завершить транзакцию (проверяет ресурсы, блокировки и т.д.).
- Если участник готов завершить транзакцию, он отвечает координатору «готов» (**VOTE_COMMIT**).
- Если хотя бы один участник не готов, он отвечает координатору «не готов» (**VOTE_ABORT**).

На этом этапе никаких изменений еще не фиксируется окончательно, но каждый участник должен убедиться, что он готов к финальному коммиту.

### ✅ **Фаза 2: Коммит или откат (Commit/Rollback Phase)**

После сбора ответов координатор решает:

- **Если ВСЕ участники готовы:** координатор отправляет команду **COMMIT** всем участникам.
    - Участники завершают транзакцию и фиксируют изменения.
- **Если хотя бы один участник не готов:** координатор отправляет команду **ROLLBACK** всем участникам.
    - Все участники откатывают изменения, транзакция считается неудачной.

## 🎯 **Пример работы двухфазного коммита:**

```
Координатор             Участник A            Участник B
    |                         |                      |
    |----- Prepare ---------->|                      |
    |                         |-- Prepare ---------->|
    |                         |                      |
    |<----- VOTE_COMMIT ------|                      |
    |                         |<---- VOTE_COMMIT ----|
    |                         |                      |
 (оба согласны, продолжаем)   |                      |
    |----- Commit ----------->|                      |
    |                         |----- Commit -------->|
    |                         |                      |
    |<----- ACK (готово) -----|                      |
    |                         |<---- ACK (готово) ---|
(Транзакция успешна!)

```

Если хотя бы один участник отвечает **VOTE_ABORT**, транзакция прерывается:

```
Координатор             Участник A            Участник B
    |                         |                      |
    |----- Prepare ---------->|                      |
    |                         |-- Prepare ---------->|
    |                         |                      |
    |<----- VOTE_ABORT -------|                      |
(Участник A не готов, откатываем изменения!)
    |----- Rollback --------->|                      |
    |                         |----- Rollback ------>|
    |                         |                      |
    |<----- ACK (готово) -----|                      |
    |                         |<---- ACK (готово) ---|
(Транзакция отменена!)

```

## 📌 **Плюсы и минусы двухфазного коммита**

### ✅ **Преимущества (плюсы):**

- Гарантия согласованности (**Consistency**) транзакций на нескольких узлах.
- Простота реализации и понимания.

### ⚠️ **Недостатки (минусы):**

- Возможны ситуации блокировок (участники ждут команды commit/rollback).
- Проблемы в случае отказа координатора (необходима логика восстановления).
- Снижает общую производительность (ожидание всех участников).

---

## 🚩 **Когда используют двухфазный коммит?**

- В распределенных реляционных базах данных.
- В микросервисах, которые затрагивают несколько независимых баз данных.
- В распределенных транзакционных хранилищах данных.

Примеры систем и сценариев, где используется 2PC:

- **Apache Kafka
- **Распределённые СУБД
- Системы обработки транзакций в банковской и финансовой сфере.

| Фаза   | Что происходит                                  | Результат                         |
| ------ | ----------------------------------------------- | --------------------------------- |
| Фаза 1 | Подготовка: проверка готовности всех участников | Либо все «готовы», либо отказ     |

|        |                                                 |                                   |

## 🚀 **Вывод (кратко):**

Двухфазный коммит — надёжный и простой алгоритм для реализации согласованных транзакций между несколькими участниками. Однако его использование требует внимания к производительности и отказоустойчивости, так как он может приводить к блокировкам и узким местам.
