Базы данных часто используют ряд специализированных структур данных для обеспечения высокой производительности при хранении и извлечении данных. Несмотря на то, что в мире существует тысячи СУБД, на деле их работу обеспечивают всего несколько ключевых структур данных.

## Hash Indexes

![[Pasted image 20250423090729.png]]

Хеш-индексация — это метод, который использует хеш-таблицу в оперативной памяти для обеспечения быстрого поиска по ключу. Каждый ключ хешируется и сопоставляется с указателем на данные на диске, что позволяет системе напрямую получить соответствующее значение с помощью одного обращения к диску.

Главный недостаток хеш-индексации заключается в том, что вся структура должна храниться в памяти. Если количество ключей слишком велико и не помещается в оперативную память, хеш-индексы работать не будут!

## Skip Lists

![[Pasted image 20250423090830.png]]

Skip list — это вероятностная структура данных, обеспечивающая эффективный поиск, вставку и удаление элементов в отсортированном связанном списке. Все операции выполняются за время O(log N), в отличие от O(N) в обычном связанном списке.

Как показано на иллюстрации выше, создаются разреженные уровни связанного списка, которые помогают выполнять быстрый поиск, устраняя необходимость последовательного прохода по всем элементам.

Поскольку skip list хранит данные в отсортированном порядке, её чаще всего используют в базах данных для управления Memtable

## Inverted Indexes

![[Pasted image 20250423091023.png]]

[[Под капотом поисковой машины | Инвертированные индексы]] — это распространённый инструмент в базах данных, поддерживающих полнотекстовый поиск. Текст разбивается на отдельные слова, после чего создаётся индекс, сопоставляющий каждое слово с идентификаторами документов, в которых оно встречается. Это позволяет быстро находить документы, содержащие определённые слова или шаблоны.

## B-Trees

![[Pasted image 20250423091221.png]]

безусловно, самая популярная структура данных в мире баз данных. Это самобалансирующееся дерево, которое хранит отсортированные данные на диске и обеспечивает поиск с логарифмической временной сложностью.

Ключевая особенность B-дерева — возможность хранения нескольких ключей в одном узле, что значительно снижает количество обращений к диску.

Почти все реляционные базы данных используют B-деревья!

## Bloom Filters

![[Pasted image 20250423091322.png]]

это еще одна вероятностная структура данных, которая используется для предварительной проверки, существует ли запись в базе данных, до того как начнется реальный поиск. Устройство фильтра таково, что он может дать ложноположительный результат, но никогда — ложноотрицательный.

Фильтры Блума чаще всего применяются в базах данных на основе LSM-деревьев, где поиск несуществующего ключа может заставить систему пройтись по всем сегментам! Если вместо этого сначала использовать фильтр Блума, время поиска по несуществующим ключам значительно сокращается.

Хороший пример — Cassandra, которая использует фильтры Блума на этапе чтения, чтобы быстро обрабатывать запросы к отсутствующим ключам.

## MemTable

MemTable — это структура данных в памяти, используемая для хранения операций чтения и записи до тех пор, пока они не будут сброшены на диск в виде SSTable-файлов.

MemTable обрабатывает как операции записи, так и чтения: все новые записи сначала помещаются в memtable, а при чтении запрос сначала обращается к memtable, поскольку в ней содержатся самые свежие данные. Когда memtable заполняется, она помечается как неизменяемая и заменяется новой. Затем фоновый процесс сбрасывает содержимое memtable в SST-файл, после чего старая memtable может быть безопасно удалена.

Существует несколько способов реализации MemTable!

## BitMap Indexes

![[Pasted image 20250423091627.png]]

Bitmap-индексы используют битовые массивы (или, проще говоря, массивы из 0 и 1) для эффективного хранения и запроса данных. Они особенно полезны для столбцов с низкой кардинальностью, то есть когда количество уникальных значений невелико.

Bitmap-индекс представляет собой серию битов, каждый из которых указывает на наличие или отсутствие определённого значения в каждой строке. Каждый бит соответствует строке в таблице, а его значение (0 или 1) показывает, содержит ли эта строка конкретное значение для индексируемого столбца.

Базы данных используют такие битовые массивы для выполнения эффективных запросов с помощью побитовых операций. Объединять битмапы с помощью операций AND и OR гораздо быстрее!

## Sorted String Table/SSTable

![[Pasted image 20250423091749.png]]

Отсортированная строковая таблица (SSTable) — это формат постоянного файла, в котором хранятся отсортированные данные. Она создаётся на основе данных из оперативной структуры MemTable и затем сохраняется на диск в виде неизменяемых файлов.

Для обеспечения быстрого поиска по файлам SST часто используются разрежённые хеш-индексы.

SSTable и MemTable вместе составляют основу баз данных, построенных на дереве LSM (Log-Structured Merge-Tree), которые широко используются во многих NoSQL-базах данных, таких как Cassandra, ScyllaDB и RocksDB.

## Prefix Trees

![[Pasted image 20250423091905.png]]

Префиксное дерево — это структура данных, оптимизированная для работы со строками или текстовыми данными. Оно формирует древовидную структуру из текстового корпуса и используется для эффективного поиска по префиксам.

Базы данных, такие как Elasticsearch, используют Префиксное дерево  для построения своих структур инвертированных индексов.

## Write Ahead Log (WAL)

![[Pasted image 20250423092032.png]]

Журнал предварительной записи (Write Ahead Log, WAL) — это одна из тех структур данных, которая одинаково популярна как в SQL, так и в NoSQL базах данных. По своей сути, это простой журнал только для добавления, в который последовательно записываются все изменения, вносимые в базу данных.

WAL обеспечивает долговечность данных и может быть использован для восстановления состояния базы данных после критических сбоев. Также он используется как буфер для записи, поскольку реальные изменения в базу данных часто выполняются пакетно с некоторой задержкой.

Такие базы данных, как Postgres, RocksDB и MySQL, используют WAL в своей внутренней архитектуре.

## Suffix Trees

![[Pasted image 20250423092123.png]]

Суффиксное дерево — это ещё одна продвинутая структура данных, которая используется для реализации полнотекстового поиска. Оно позволяет эффективно искать вхождения заданного шаблона в большом массиве текста.
